# CUMCM 国奖论文行文风格

## 证据基础与共识分层

本规范基于教育部"大学生在线"官方展示的 **2021–2025 年 44 篇国奖论文原文**（摘要页全读 + 正文抽样），并对照官方《论文格式规范》与评审文件。风格断言分三层，写作时按此把握分寸：

- **【共识】** 几乎所有国奖论文都这么做——照做即可，不做是扣分项；
- **【主流】** 多数国奖论文这么做——默认照做，个体偏离不致命；
- **【加分/趋势】** 约半数或近年上升的做法——做了加分，不做不扣分。

风格服务对象：**初评单篇只读 5–10 分钟**，官方四条标准（假设的合理性、建模的创造性、结果的正确性、文字表述的清晰程度），获奖者共识"摘要+结果基本决定省一还是省二"。目标是让快读评委顺着"摘要 → 图表 → 结论"就能复述你做了什么、得到什么数。

## 硬性格式（官方规定，违反影响评奖资格，提交前以当年修订稿为准）

- 电子版 PDF **第一页必须为摘要专用页**（含标题、关键词，不超过一页）；页码从摘要页起，页脚居中【44/44 遵守】；
- **正文不要目录**；正文（含摘要）尽量 ≤20 页，上限 30 页；
- 附录页数不限，**必须含全部完整可运行源码**，缺源码或结果与论文不符 → 取消评奖资格；
- 全文与支撑材料**匿名**；引用他人成果必须列参考文献（GB/T 7714）并在正文标注；
- A4、页边距 ≥2.5cm；承诺书与编号专用页不放入电子版。

## 论文骨架

```
摘要专用页（独占一页，纯文字，不放图）
一、问题重述        （1.1 问题背景；1.2 问题提出/重述，逐问加粗标签改写）
二、问题分析        （逐问一小节：本问本质是什么类型的问题 + 方法路线；
                     可放"文章总体思路如图1所示"框架图——约1/4国奖有，非必备）
三、模型假设        （3–6 条直陈式编号列表）
四、符号说明        （三线表：符号/含义/单位）
五 ~ N、按问题分章   （每问：分析 → 模型建立 → 求解算法 → 结果与分析）
模型检验（可选独立章）/ 模型评价与推广
参考文献（GB/T 7714）
附录（支撑材料清单 + 完整源码 + 详细结果表）
```

顺序变体：假设与符号说明放在问题分析之前（"重述→假设→符号→分析"）同样是国奖写法；"问题重述与分析"合并成一章也常见。二选一保持全文一致即可。

## 摘要：全文生死页

**【共识】44/44 篇的写法**：

- 摘要独占一页、纯文字无图表、页码从 1 起；
- **按问题分段**，每段"方法 → 求解 → 结果"完整闭环；
- **关键数值结果写入摘要且带单位/百分号**（MW、元/件、%、海里……），每问 2–5 个；
- 段首引导词：**"针对问题X"（约七成）**或"对于问题X""问题X："，加粗起段；
- 篇幅约 **600–1200 字、4–6 段**（个别国奖短至 450 字）；
- 关键词 **3–7 个（4–5 个为主）**，近年多数用**空格**分隔（分号/逗号也有国奖在用），标签写"关键词"。

**【主流】**：

- 开头总起段：2–3 句背景后用"本文……"一句点题；约 1/5 的国奖**无背景段直接从"针对问题一"开写**——两种都合格，背景绝不超过 3 句；
- 人称以"**本文**"为主（每段 1–2 次）；"**我们**"出现在约 1/3 的国奖论文中，多用于动作句（"我们建立了……"），与"本文"混用可接受，但不要通篇"我们"；
- **模型名/方法名/算法名加粗**（如"状态-决策模型""模拟退火""LMM"）；
- 数据题在摘要中写明结果文件指引（"将结果存入 result1.xlsx""详见表 2"）是常见做法。

**【加分/趋势】**：

- **关键数值加粗**：2025 年国奖 5/5 全部数值加粗，2024 年约半数——最新趋势，推荐做；
- 定性结论词加粗（"显著负相关"）；英文方法名加粗（LSTM、GPR）；
- 2025 年出现"本文创新性在于：一是……二是……三是……"独立段，可用于有明确创新的论文。

**摘要四要素**（每问一段内按序回答）：解决了什么问题 → 用什么模型与方法（点名即可，不展开推导）→ 得到什么数值结果（带单位）→ 结果说明什么（一句结论或稳健性）。

反例（国奖大忌）："针对问题一建立了合理的数学模型，采用有效的算法进行求解，得到了较为理想的结果"——无模型名、无数值、无结论。正反例与逐问句式见 `references/templates.md`。

## 各章行文规则

| 章节 | 【共识/主流】标准 | 常见错误（评委反感点） |
|---|---|---|
| 问题重述 | 【共识】"1.1 问题背景 + 1.2 问题提出"两小节，用自己的话改写压缩、逐问加粗标签列表，保留原题参数；背景可配结构示意图或文献标注 | 整段照抄原题（44 篇无一照抄——评委刚读过题面） |
| 问题分析 | 【主流】逐问一小节纯文字，句式"该问本质上是一个……问题"，点明方法路线 | 只抄题不说思路；分析文字与摘要雷同 |
| 模型假设 | 【共识】3–6 条直陈式编号列表，一句话一条；【加分】每条附一句依据或影响范围（"为了简化模型……"，2025 年多见） | 堆"数据真实可靠""不考虑其他因素"式万能假设；假设与建模脱节 |
| 符号说明 | 【共识】三线表（符号/含义/单位），按出现顺序，可加"（续）"表 | 一符多用；漏单位 |
| 建模与求解 | 【共识】图表有编号有标题（图题居中图下、表题表上），正文必有"由图X可知""如表X所示"式显式引用；写清算法原理与参数；重要结果集中成表 | 图表不引用；"采用 MATLAB 求得："直接甩结果；公式连排无文字衔接 |
| 灵敏度/检验 | 【共识】给出扰动后的具体数值和结论是否变化 | 只写"经检验，模型稳定性良好"——零信息 |
| 模型评价 | 【主流】优点具体、缺点只写影响小可改进的；国奖常见收尾句"最后对模型的优劣进行了讨论并提出改进意见" | 自曝致命缺陷；玩弄标新立异的概念 |
| 参考文献 | 【共识】GB/T 7714，正文引用一一对应；C 题数据类论文背景常带文献叙述（"Wang 等人(2013)研究证实……"） | 链接充数、正文不标注 |

## 语言语域

- 【主流】"本文"为默认人称；"我们"可少量用于动作句，全文风格统一；
- 【共识】正式书面语。不写口语（"扛不住""一边倒""只赔不赚的空转"→"估计误差足以逆转决策""系统退化为无正产出的循环"）；
- 【共识】不中英混排：respectively、worst-case 裸用 → 删掉重写/"最坏情形"；
- 【共识】少用括号补注与破折号追加，一句一个主张，每段先给结论句再展开；
- 工程流程词翻译成评委语言："11 项质量门"→"11 项一致性检验"、"单源生成"→"论文数值由统一结果文件生成并经独立复核"；
- 严谨性放正文与检验章（守恒恒等式、独立仿真、极限回归都是加分项）；**摘要只留每问 2–5 个代表性数值**，不要把残差、误差率全塞进去。

## 提交前风格自查清单

本清单必须**逐条回显**在交付说明中（格式："第 N 条：通过/不适用——证据"），没有回显的条目视为未检查——2024C 实战评审中，第 10、11 条正是被跳过未回显、最终被外部评委点名的两条。机器可判定的条目（第 4、7、10、11、13、15 条）优先用 math-modeling-pro 的 `scripts/check_official_compliance.py` 判定，不要目测。

1. 摘要独占一页、逐问分段、每问有模型名 + 算法 + 带单位数值？
2. 加粗落在逐问引导词、模型/方法名（以及推荐的数值）上？
3. 关键词 3–7 个、分隔符全文统一？
4. 无目录，页码从摘要页起，正文 ≤30 页（尽量 ≤20）？
5. 问题重述是改写而非照抄？逐问有加粗标签？
6. 每条假设一句话、无万能假设？
7. 每张图表在正文有显式引用？
8. 灵敏度/检验有具体数值？
9. 人称统一（本文为主）、无口语、无英文残留、无括号堆叠？
10. 参考文献与正文引用一一对应（每条 [n] 都在正文出现，正文无悬空引用）？
11. 附录代码完整可运行、输出与正文一致？全文匿名？
12. 终极测试：只读摘要 + 图表 + 结论，能否复述全文做了什么、得到什么数？
13. 编号公式在正文按编号回引（如"由式(3)可知"），符号说明表被正文至少引用一次？
14. 数据类论文摘要写明结果文件指引（如"结果分别填入 result1_1.xlsx 与 result1_2.xlsx"）？
15. 支撑材料清单与压缩包逐项一致（文件名含目录名；打包晚于写作时先改清单再压缩）？

## 风格修订工作流（改已有论文时必走，顺序不可跳）

风格标准（上文）回答"改成什么样"；本节回答"怎么改才不漏"。经验教训：一次"grep 词表→改命中项"的流程实测漏改率约 40%，必须按以下闭环执行。

**第 1 步：全量扫描。** 对论文项目的**全部**源文件（.tex/.docx 提取文本）跑下方病灶词表。豁免规则：只豁免**代码清单本体**（`lstinputlisting`/`minted`/代码块内文本，且须与支撑材料源码逐字一致，改了反而制造不一致）；附录中的说明文字、清单表格、小节标题是散文，**必须扫**。

**第 2 步：语义通读。** 词表未命中 ≠ 干净——词表永远不完备（实测有"单一来源"漏过"单源"的变体盲区）。对每段问一句：这句话像期刊审稿人会写的吗？冒出"契约、锚点、门、链路、单源"这类流程文档词汇就是病灶。

**第 3 步：修改后验证门（四项缺一不可）。**
1. 重编译成功（LaTeX/Word 均需重新生成 PDF）；
2. 对**生成的 PDF 提取全文**再跑一遍病灶词表，命中数必须为 0（对 PDF 扫而非对源码扫，才能抓住编译产物里的残留）；
3. 渲染抽查修改点所在页面（加粗/分隔符/公式是否正常显示）；
4. 官方硬条款门：运行 math-modeling-pro 的 `scripts/check_official_compliance.py --paper <PDF> --tex <论文目录> [--support <ZIP>] [--log <编译日志>]`，覆盖正文引用闭环、附录代码完整性、Overfull 残留、支撑清单↔压缩包一致、摘要首页。风格修订最容易顺手破坏的恰是这些硬条款（改摘要动掉关键词、改附录动掉代码清单），任何 FAIL 修复后重跑。

**第 4 步：诚实披露。** 向用户报告：改了几处、扫了哪些文件、豁免了什么及理由、遗留风险清单、逐条自查清单回显结果。有意保留项（如代码注释）要明确说明为什么不改。

### 病灶词表（机检用初始版，可持续扩充）

```
我们（正文密集出现时）  respectively  worst-case  knife-edge  trade-off
质量门  单源  单一来源  机器比对  交付契约  交付物  锚点  链路
扛不住  一边倒  老办法  空转（比喻义）  不抵费用  可以定价  划算（口语段落）
翻转为（可保留"转为"）  良好（"稳定性良好"类空话）
```

注意变体：词表项可能以不同措辞出现（"单源"vs"单一来源"），语义通读兜底。
