# 创新机制与强制发散

本文件回答"按流程做出的合格论文如何变成有区分度的论文"。四个机制的共同点：把"想到"变成流程的必经步骤，由阶段门强制执行，而不是依赖灵感。

评审事实：绝大多数国奖论文的"创新"不是发明新算法，而是 ①利用了题目某处特殊结构；②从第一性原理自主推导而非套用现成模型；③发现了数据中非显然的规律并纳入建模。这三个来源都可以被流程逼出来，逼不出来才是真的没有。

## 机制一：发散建模门（Stage 2，查矩阵之前）

**规则：先自建，再查表。** 对每个子问题，在打开 `model-selection-matrix.md` 之前：

1. 写出 2--3 个数学本质不同的建法（例如：同一问题分别表述为优化 / 机理仿真 / 统计估计；或解析推导 / 数值离散 / 概率近似；或整体建模 / 分段建模）。
2. 每种建法各写三行：揭示了原问题的什么、掩盖了什么、求解代价多大。
3. 之后才查矩阵。矩阵条目与自建方案冲突时，必须书面说明取舍理由，不得因为矩阵"首选"就放弃自建方案。

合格判据：如果几个建法中没有任何一个利用了题目独有结构（全都像通用模板），发散不合格，回到题目重读后再发散。

## 机制二：题目特殊结构识别表（Stage 2）

对整道题（不是每个子问题）强制列出 2--3 处"不一般的地方"：

| 识别角度 | 典型信号 | 创新点形态 |
|---|---|---|
| 结构对称性/周期性 | 旋转对称、循环边界、平移不变 | 降维、解析解、缩放性质 |
| 约束的特殊形状 | 单调、线性、可分离、稀疏耦合 | 复杂度骤降或精确算法可行 |
| 退化/极限情形 | 参数趋零、边界退化、小规模可枚举 | 极限检验 + 机理洞察 |
| 数据非常规来源 | 实验误差结构已知、面板/截面混合、选择性偏差 | 误差建模或偏差修正本身就是贡献 |
| 题目问法的暗示 | "证明""说明为什么""论证策略" | 要求结构性结论而非纯数值 |

要求：至少一处特殊结构被模型设计**真正利用**（体现在公式、算法或复杂度上），并进入贡献证据表（`validation-and-contribution.md` 第三节）；只识别未利用的条目在论文中降为普通分析结论，不得计入贡献。

示例（仅说明机制，非可复用解法）：某年链式螺线题的速度缩放性质，来自识别出"链式距离约束对速度是线性的"这一结构——把最难的最优化子问题化简为一维缩放。识别发生在建模前，不在求解后。

## 机制三：数据假设循环（数据类赛题）

EDA 完成后、模型选择前，强制产出"可检验假设清单"：

1. 从数据审计与初步探索中写下 3--5 条候选假设。必须是**非显然**的：不是"X 与 Y 相关"这类查表式结论，而是有机理或业务含义、且不完全在预期内的命题（如"某类样本对价格变动的响应显著弱于其余样本"）。
2. 每条假设标注检验方法与预期证据（分组对比、统计检验、图）。
3. Stage 3 求解时实际检验。被证实的假设必须进入模型（作为特征、分层结构、权重或约束），并在论文中作为发现陈述；被证伪的同样写入论文——证伪本身就是工作量。
4. 合格判据：至少一条假设真正改变了模型设计；一条都没有进入模型的清单等于没有做。

## 机制四：洞察盲区红队审（Stage 4，自审第一轮 1.4）

论文成稿后增加"专家视角盲区审查"，逐个子问题回答：

1. 这道题的哪一部分，训练有素的评审会期待看到而论文没有处理？（特殊情形、反例、边界条件、量纲、极端数据）
2. 当前选定的框架掩盖了什么可能更好的问题表述？（对照机制一的其余建法）
3. 结果里有没有"太顺滑"的地方——是否存在没有任何反直觉现象被讨论？全部符合直觉通常意味着没有看细。
4. 与题目最直接联想到的朴素方法相比，除了精度还在哪个层面不同？层面从高到低：问题表述 > 模型结构 > 算法 > 参数调优。只停留在下面两层不构成创新。

处理规则：发现盲区后能补则补实验或推导；确实不能补的，在模型评价中如实写为局限。禁止为填补盲区而编造结果。

## 与现有流程的接口

- 机制一的产出进入 Stage 2"候选比较"和贡献证据表的"对照方案"列。
- 机制二、三是 Stage 4"本题贡献 2--4 项"的主要来源；贡献表述仍按 `validation-and-contribution.md` 的三类措辞约束，"方法创新"必须绑定可观察差异。
- 机制四在 `self-review-framework.md` 第一轮 1.4 执行，不通过不得进入第二轮。
- 时间不足时的取舍：机制一、二不可省略（成本主要是思考时间而非算力）；机制三在数据类赛题必做；机制四至少完整执行一遍。
