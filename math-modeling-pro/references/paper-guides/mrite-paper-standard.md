# 可审计数学建模论文标准

本文件是项目质量标准，不是官方格式规范。官方要求以 `../official-compliance.md` 和当届竞赛官网为准。

## 产物契约

论文中的每个关键数字都应能追溯到：输入文件、处理步骤、模型参数、运行入口和结果文件。建议维护一份结果索引，记录“论文位置 -> 结果字段/图表 -> 生成脚本”。

## 源码组织

- 一个清晰的总入口或逐问题入口；路径基于项目根目录，不依赖开发者个人目录。
- requirements/environment 文件记录非标准依赖。
- 计算和绘图可分开运行；固定或记录随机状态。
- 结果文件使用题目要求的模板副本，保存前检查字段、sheet 和精度。
- 独立验证器不复用被测程序的关键逻辑，至少验证格式、不变量、约束和指纹。

## LaTeX 组织

- 主文件只负责包、字体、标题、章节输入和全局样式。
- 可按章节拆分，但不强制每问固定为几个文件。
- 不通过手工换页掩盖图表浮动或标题孤行；使用自然排版、浮动屏障或条件式空间。
- 短表和长表按用途选择；列宽经过实际编译验证。
- 公式、图和表均有稳定标签且在正文引用。
- 附录列出支撑材料，并包含生成最终结果的全部完整源代码。

## 论文内容检查

- 摘要一页内，覆盖任务、方法、关键结果与验证。
- 假设可解释其必要性和结论影响，不写“数据真实可靠”等空假设。
- 参数有数据、文献、标定或明确情景依据。
- 结果先给数值，再解释意义、边界和不确定性。
- 优缺点针对实际模型；缺点与改进一一对应。
- 参考文献真实存在、正文引用集合一致。

## 图表策略

图数和公式数不是质量指标。仅生成能承担以下任务的图表：数据审计、模型结构、核心结果、基线比较、误差、敏感性、空间/时间分布或决策权衡。重复表达同一信息的图应删减或合并。

## 编译与交付

Windows 使用 `../../scripts/compile_paper.ps1`；其他平台按 `../cross-platform-execution.md` 执行。日志无目标警告后仍要渲染抽检页面。

最终提交前运行：

```text
python <skill>/scripts/audit_project.py --project <目录> --paper <PDF> --support <ZIP> --log <LOG>
```

通用脚本不判断模型真实性；项目必须另有 Stage 3 领域验证器和隔离复现记录。
