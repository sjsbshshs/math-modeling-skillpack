# 论文↔结果一致性门（数据完整性）

本文件治理"结果对了、论文错了"这一类事故。以下教训来自一次真实评审，已通用化：表格生成代码把循环枚举序号当时间下标（t=60 列取到 t=1 秒的值），错值流经 结果摘要 JSON → 表格生成 → 论文 → PDF → 提交包，六层无人拦截；而同一个 JSON 里就躺着能揭穿它的正确锚点值，控制台还打印过正确值。全部实现级检验（弦长残差 <1e-11）照样通过——错位的几何仍然自洽。结论只有一句：**实现级残差通过不等于数值正确，必须单独立一道"论文↔结果"门。**

## 一、单一来源原则

- 论文中所有数值只能由结果文件（xlsx/csv/结果摘要 JSON）经脚本生成进入 LaTeX；禁止手抄数字进 tex，禁止在表格生成代码里对数据做第二次挑选或重排。
- 表格取数必须按**语义键**（时刻、对象 ID、行名）索引，禁止把循环枚举序号当数据下标。典型陷阱：`for i, t in enumerate([0, 60, 300])` 后取 `data[i]`——第 k 列恰好显示 t=k 秒的值，肉眼极难发现，且与全部自洽性检验不冲突。
- 取数后立即在 stdout 打印 2--3 个锚点（首/末时刻的已知声称值）并与正文声称值比对；矛盾必须死在控制台，不能活到 PDF。

## 二、交付契约双向绑定

Stage 1 交付契约的每条条目（文件名、sheet、字段、精度、**行序**、表头）必须标注两侧落点：结果文件侧 + 论文表格/图侧，两侧分别验收。只查数据侧不查论文侧，就会出现"xlsx 行序完全正确、论文表行序错误"的分裂。题目中"格式见表 1/表 2"这类规定同时约束两侧。

## 三、一致性硬门（三层，全部机器执行）

用 `scripts/check_paper_consistency.py`（复用 audit_project 的 PDF 文本抽取）：

1. **清单自洽**：结果摘要中登记的 `cross_checks` 全部成立。每问至少登记 1 条**题目语义级不变量**——由题目语义直接推出、与实现无关的关系（位移≈速度×时间、起点在给定边界、t=X 极径=摘要声称值等）。实现级残差再漂亮也替代不了这一层。
2. **清单↔结果文件**：`paper_claims` 中每个数字能从其声明的 source（xlsx 单元格/sheet、csv、JSON 路径）按声明精度复现。
3. **清单↔PDF**：编译后运行，每个登记数字（按 2--6 位小数变体归一化匹配）能在 PDF 文本中找到；`--strict` 时任一缺失即失败。

三个时机：表格生成后（第 1、2 层）、每次编译后（第 3 层）、冻结前（三层全跑）。任何一层失败不得进入下一步骤，修复后从受影响的最早一步重跑。

## 四、paper_claims / cross_checks 约定

在项目的结果摘要 JSON 中增加两个块（键名固定，工具按此识别）：

```json
{
  "paper_claims": [
    {"key": "p1_head_pos_60s", "value": [5.799209, -5.771092],
     "source": "result1.xlsx#位置!B2", "decimals": 6}
  ],
  "cross_checks": [
    {"a": "p1.r_head_300s", "b": "p1.table.t300_h0.r", "tol": 1e-6}
  ]
}
```

- `source` 支持 `文件#sheet!单元格`、`文件#sheet`（在整表内搜索）、`文件#json点路径`。
- `cross_checks` 的 `a`/`b` 是 JSON 内点路径或数字字面量，按 `tol` 近似比较；这是把"失败判据表"里的语义不变量变成可执行断言的落点。
- 没有这两个块的旧项目：工具以扫描模式运行（advisory），报告中列出"未能确认"项；`--strict` 模式下未登记声明视为未通过。

## 五、检验声明绑定运行证据

检验章每条"已验证/逐项一致"的声明必须绑定可复核的运行证据：哪个脚本、哪次输出、哪份报告文件（含一致性报告的通过时间戳）。无运行证据的一致性声明按**未验证**处理，不得写入论文。一致性报告随支撑材料提交。

## 六、交叉引用完整性

代码注释里"见论文 X.Y 节"这类指向会随正文重组而腐烂。工具 `--lint-xref` 扫描项目源码中的章节引用，与主 tex 的 `\section`/`\subsection` 实际编号比对；悬空引用必须修复或删除。同类问题：正文引用的图表号、附录声称的"详见"目标。

## 七、与现有流程的关系

- 本门是 `quality-gates.md` 最小必做集第 5 条的实现细则；题目语义级不变量来自该文件"失败判据表"新增行。
- Stage 6"比对关键数值"的机器部分由本工具承担；当届官方规则核对、模型物理真实性、摘要质量仍属人工/项目级验证（见 `official-compliance.md` 的自动/人工边界）。
- 工具查不出它不知道的语义错误——cross_checks 的质量取决于失败判据表写得是否认真，这一步没有捷径。
